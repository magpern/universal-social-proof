# Universal Social Proof — v1.1 Feature Plan (Authoritative)

> **Status:** APPROVED FOR IMPLEMENTATION  
> **Baseline:** `7baa731a011e49419e3c358797ebaa8203085f7e` (runtime `1.0.2`)  
> **Target:** annotated `v1.1.0`  
> **Out of scope:** reopen M7; rewrite `v1.0.x`; reimplement plugin-row links

## Principles

1. Real social proof only — never fabricate purchase or cart activity.
2. Cart notifications claim only that a successful WooCommerce add-to-cart occurred.
3. Upgrade from `v1.0.2` remains purchase-only until the operator enables cart.
4. Plugin Settings | Diagnostics links (shipped in `v1.0.2`) are regression-only.

## Event types

| Type | Meaning | Provenance |
|------|---------|------------|
| `purchase` | Qualifying WC order line (unchanged) | `source_order_id` + `source_item_id` |
| `add_to_cart` | Successful WC cart add | No order/item provenance; `source_*` NULL |

Explicit `event_type` column. Never infer type from null provenance alone.

## Schema (`DB_VERSION` → `20260907v11a`)

1. Add `event_type varchar(16) NOT NULL DEFAULT 'purchase'`.
2. Backfill existing rows → `purchase`.
3. Allow NULL `source_order_id` / `source_item_id` (cart).
4. Drop `UNIQUE source_order_item`; add `UNIQUE event_source (event_type, source_order_id, source_item_id)`  
   (MySQL allows multiple cart rows with NULL provenance).
5. Add `KEY status_type_occurred (status, event_type, occurred_at)`.
6. Idempotent migration; no table rebuild.

## Cart capture

- Hooks: `woocommerce_add_to_cart` (primary); Store API / AJAX still funnel through WC cart add when successful.
- Capture only after Woo accepts the add.
- Request-local idempotency keyed by `(product_id, variation_id, quantity)` for the current request — one logical add → one USP event.
- Country: UGC at add time → `country_code` or NULL. No IP/session/customer persistence.
- Cart source disabled → do not capture.
- Later cart removal does not suppress historical cart events.

## Sources & freshness

| Setting | Default | Range |
|---------|---------|-------|
| `purchase_enabled` | `true` | bool |
| `cart_enabled` | `false` | bool |
| `retention_days` (purchase window) | preserved / 60 | 7–90 |
| `cart_retention_minutes` | 60 | 5–1440 |

Purchase disabled: capture continues; selection skips purchases.  
Cart disabled: no capture; selection skips cart.

## Templates

- `template` → purchase template (migrated).
- `cart_template` new.
- Defaults:  
  - purchase: `Someone in {{country}} purchased {{product}}` (with country-absent fallback)  
  - cart: `Someone in {{country}} just added {{product}} to their cart`
- Country absent → grammatically valid fallback without empty “in ”.

## Selection mixing

One stream, K≤10, product budget ≤20, UGC ≤1/request.

1. Fill with eligible purchases (geo/PDP as today, purchase cutoff).
2. Fill remaining slots with eligible cart (cart cutoff, same geo/eligibility).

No admin weighting slider.

## Appearance

Settings (CSS variables on `.usp-toaster`):

- `position`: `bottom-left` \| `bottom-right`
- `background`, `text`, `accent` colors
- `radius`, `shadow` preset
- `show_product_image`, `show_close`
- `custom_css` (advanced, bounded, admin-trusted CSS)

Default toast redesigned to a polished compact card; reduced-motion preserved.

## Settings version

`usp_settings_version` → **2**. Idempotent migrate from v1; preserve all existing keys; add cart/appearance defaults; cart disabled.

## Privacy / uninstall

Cart rows: no visitor identity. Uninstall drops all USP-owned options/events including new fields.

## Performance

Prefer type-scoped candidate queries over naive full double M5 pipelines. Record budgets in closure.

## Release

Runtime `1.1.0` on feature branch; Stable stays `1.0.2` until `release/v1.1.0`.
